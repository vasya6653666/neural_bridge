# CAST Imaging → AWS Transform Custom Power

## Overview

This power delivers end-to-end application modernisation in two distinct phases:

- **Phase 1 (Automated)**: Deep structural assessment using CAST Imaging MCP, data-driven probing to determine the optimal modernisation path, and generation of a fully-structured Phase 2 transformation definition. No code changes — purely analytical.
- **Phase 2 (Execution)**: The generated TD is executed via AWS Transform custom with CAST Imaging MCP still available for verification, caller/callee analysis, and impact assessment during code transformation.

The separation ensures human oversight between analysis and execution — the user reviews, edits, and approves the generated TD before any code is touched.

## Capabilities

### Phase 1: Assessment & TD Generation (CAST Imaging)

- **Application Discovery**: List all applications available in the CAST Imaging environment
- **Architecture Analysis**: Explore application architecture at multiple abstraction levels (layer, component, sub-component, technology-category, element-type)
- **Quality Assessment**: Review quality insights including CVEs, structural flaws, ISO-5055 violations, cloud readiness, and green/sustainability patterns
- **Transaction & Data Flow Analysis**: Understand application behaviour through transaction and data call graph exploration
- **Dependency Mapping**: Analyse inter-application and intra-application dependencies, packages with versions
- **Database Exploration**: Inspect database tables, columns, and data relationships
- **Code-Level Inspection**: Retrieve source code snippets, callers/callees, and violation locations with exact file paths and line numbers
- **Data-Driven Probing**: Ask targeted questions based on specific findings (not generic menus)
- **TD Generation**: Produce a fully-structured Phase 2 transformation definition with MCP verification guidance

### Modernisation Patterns Supported

There are 4 primary categories, each with distinct sub-patterns:

| Category | Sub-Patterns | Examples |
|----------|-------------|----------|
| **Technology Upgrade** | Language Version Upgrade | Java 8→17, Python 3.8→3.12, Node.js 16→22 |
| | Framework Version Upgrade | Spring Boot 2→3, Angular 14→18, Django 3→5 |
| | Framework Migration | Struts→Spring Boot, jQuery→React, Express→Fastify |
| **Security Remediation** | CVE Remediation | Vulnerable dependency upgrades, code-level vulnerability fixes |
| | Structural Flaw Fixes | CWE violations — SQL injection, XSS, resource leaks, error handling |
| **Code Refactoring** | Dead Code Removal | Unused methods, classes, stored procedures |
| | Complexity Reduction | Extract methods, decompose conditionals, simplify hotspots |
| | Coupling Fixes | Reduce inter-component dependencies, dependency inversion |
| | Idiom Modernisation | Legacy patterns → modern language/framework idioms |
| **Cloud Readiness** | Cloud Blocker Resolution | Hardcoded configs, platform-specific APIs, stateful sessions |
| | State Externalization | Local files→S3, sessions→Redis/DynamoDB, cache→ElastiCache |
| | Containerization | Dockerfile, deployment manifests, health checks, env config |

An application may require a **combination** of sub-patterns across categories.

### Phase 2: Execution (AWS Transform Custom)

Phase 2 uses the TD generated by Phase 1. It:

- Takes the generated TD as its transformation definition
- Executes via AWS Transform custom (local or remote mode)
- **Requires CAST Imaging MCP access** during execution for verification, caller/callee analysis, and impact assessment
- Supports local execution (1-9 repos) or remote execution (10+ repos via AWS Batch/Fargate)

## Workflow

1. **Connect** — Verify CAST Imaging MCP server is responding
2. **Select Application** — List available applications, user picks one
3. **Deep Assessment** — Gather comprehensive data: architecture, quality, dependencies, transactions, data flows, advisors (with tiered violation retrieval)
4. **Present Findings** — Show quantified assessment summary with specific counts and locations
5. **Probe** — Ask data-driven questions to determine modernisation path (never generic menus)
6. **Pattern-Specific Intelligence** — Gather focused data for the chosen pattern (violations with locations, code snippets, file paths)
7. **Generate Phase 2 TD** — Produce a fully-structured transformation definition with MCP verification guidance
8. **Handoff** — Present the TD and instruct the user on reviewing and executing it

## MCP Server

This power requires a CAST Imaging MCP server connected to your CAST Imaging instance. The MCP server exposes CAST Imaging's REST API as MCP tools. It is required in **both phases** — Phase 1 for assessment, Phase 2 for verification during execution. On first use, the power will prompt you for your CAST Imaging URL and API key to configure the connection.

### Tool Categories

**Portfolio-level** (cross-app):
- `applications` — List all apps
- `applications_quality_insights` — Quality across portfolio
- `applications_dependencies` — Inter-app dependency map

**Application-level** (single app deep-dive):
- `stats` — Size, complexity, technologies
- `architectural_graph` / `architectural_graph_focus` — Architecture at multiple levels
- `quality_insights` — CVEs, flaws, ISO-5055, cloud, green
- `quality_insight_violations` — Exact violation locations (file + line)
- `packages` / `package_interactions` — External dependencies with versions and usage
- `transactions` / `transaction_details` — Business flows
- `data_graphs` / `data_graph_details` — Data entity interactions
- `advisors` / `advisor_occurrences` — Migration/modernisation rules and findings
- `application_database_explorer` — DB tables and columns
- `application_iso_5055_explorer` — ISO-5055 characteristics
- `inter_applications_dependencies` / `inter_app_detailed_dependencies` — Cross-app coupling

**Object-level** (code inspection):
- `objects` — Search/filter code objects
- `object_details` — Callers, callees, code snippets, insights
- `source_files` / `source_file_details` — File-level analysis
- `transactions_using_object` — Which flows use an object
- `data_graphs_involving_object` — Data flows through an object
- `pathfinder_hierarchy_details` — Execution paths and hierarchy exploration
